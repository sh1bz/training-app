This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server (http://localhost:5173)
- `npm run build` — production build via `vite build`
- `npm run preview` — preview the production build
- `npm run check` — run `svelte-kit sync` then `svelte-check` for type/Svelte diagnostics (this repo's only "lint/test" gate)

There is no test runner configured. Before declaring work complete, run `npm run check`.

## Environment

The Supabase client is initialized at module load from `$env/static/public`, so **`PUBLIC_SUPABASE_URL` and `PUBLIC_SUPABASE_ANON_KEY` must be present in `.env`** or `npm run dev` / `build` will fail at import time. Copy from `.env.example`. Both are public (browser-exposed) by design — never introduce a service-role key under the `PUBLIC_` prefix.

## Architecture

SvelteKit 2 + Svelte 5 (runes mode, e.g. `$state`) on TypeScript, with `@sveltejs/adapter-auto` (deploy target inferred at build time). Supabase JS client is the only runtime dependency.

- `src/lib/supabase.ts` — single shared `SupabaseClient` instance, exported as `supabase`. Import via the `$lib` alias (`import { supabase } from '$lib/supabase'`). Reuse this client; do not call `createClient` elsewhere.
- `src/routes/+page.svelte` — current entry page; pattern for any new route is a `+page.svelte` (and optionally `+page.ts`/`+page.server.ts`) under `src/routes/`.
- `src/app.d.ts` — extend the `App` namespace here to type `locals`, `PageData`, etc., once server hooks/load functions are added.
- `src/app.html` — root HTML shell.

`tsconfig.json` extends `./.svelte-kit/tsconfig.json` (generated by `svelte-kit sync`); if path aliases or types look broken, run `npm run check` first to regenerate it.
