## Commands

- `npm run dev` — start the Vite dev server (http://localhost:5173)
- `npm run build` — production build via `vite build`
- `npm run preview` — preview the production build
- `npm run check` — run `svelte-kit sync` then `svelte-check` for type/Svelte diagnostics (this repo's only "lint/test" gate)

There is no test runner configured. Before declaring work complete, run `npm run check`.

## Architecture

SvelteKit 2 + Svelte 5 (runes mode, e.g. `$state`, `$derived`, `$effect`) on TypeScript, with `@sveltejs/adapter-auto` (deploy target inferred at build time — works out-of-the-box on Vercel/Cloudflare/Netlify).

The app is currently **frontend-only** with an in-memory mock store. No backend wired up yet — `@supabase/supabase-js` is still a dependency for when we add persistence, but no module imports it.

### Data model (`src/lib/types.ts`)

`Program → WorkoutTemplate[] → ExerciseTemplate[]`. Each exercise carries `targetSets`, `targetRepsMin`/`Max`, `workingWeight`, `restSeconds`. Starting a workout snapshots the templates into a `Session` with `SessionExercise[]` and `LoggedSet[]` (weight × reps × done).

### State (`src/lib/store.svelte.ts`)

Single `store` instance using class fields with `$state(...)`. Exposes mutations for programs/workouts/exercises and session lifecycle (`startWorkout`, `updateSet`, `addSet`, `finishWorkout`, etc.). Do not call `$state` at the module top level — wrap state in a class so `.svelte.ts` runes work.

### Routes

- `/` — Summary (active session banner, weekly stats, recent)
- `/programs`, `/programs/[id]`, `/programs/[id]/edit`
- `/programs/[id]/workouts/[wid]/edit` — exercise target editor
- `/workout/[id]` — active session with rest timer
- `/history`, `/history/[id]`

### Design system

Apple Health-inspired: pure black background, dark-elev cards, system blue accent, floating pill tab bar with `backdrop-filter`. All colors live as CSS vars in `src/app.css` (`--bg-elev-1`, `--blue`, `--green`, etc.). Use `system-ui` font stack. Components avoid Tailwind — scoped Svelte `<style>` blocks consume the global vars.

### App shell

- `src/app.html` — meta tags for `theme-color`, `apple-mobile-web-app-capable`, `viewport-fit=cover`. Required for proper mobile/PWA feel.
- `src/routes/+layout.svelte` — imports `app.css` and renders the floating tab bar.
- `src/app.d.ts` — extend `App` namespace here once server hooks/load functions are added.

`tsconfig.json` extends `./.svelte-kit/tsconfig.json` (generated by `svelte-kit sync`); if path aliases or types look broken, run `npm run check` first to regenerate it.

## When adding Supabase back

Reintroduce `src/lib/supabase.ts` as a single shared client (`createClient(url, key)`), import via `$lib`. Both env vars must use the `PUBLIC_` prefix — never put a service-role key under `PUBLIC_`. Set them in `.env` locally and as Project Environment Variables on Vercel.
